# Skyrim Mod Factory — AI Texture and Material Pipeline

Created: 2026-09-24
Status: canonical AI-assisted asset workflow

## Objective

Let an agent generate, edit, tile, derive and validate Skyrim texture/material assets while keeping:
- artistic source generation separate from engine-format conversion;
- reproducible workflow/seed/model provenance;
- NIF/material semantics explicit;
- renderer-specific requirements explicit;
- AI generation behind rights/quality gates.

## AI generation plane — ComfyUI

Preferred integration candidate: Comfy MCP / local ComfyUI.

Agent operations:
- text-to-image concept/texture generation;
- image-to-image refinement;
- ControlNet/reference-guided edits;
- upscale;
- mask/inpaint/outpaint;
- saved workflow execution;
- model/LoRA selection;
- batch seed/parameter exploration.

### Paid-node safety

Comfy workflows can call hosted/partner APIs. Agent OS must classify each workflow:
- local-only;
- known paid provider;
- unknown/custom network node.

Paid or unknown external generation requires the user's configured spending policy/approval. Local ComfyUI itself is not evidence that every node is free/offline.

## PBR/material derivation

Candidate helper: TextureAlchemy-style ComfyUI workflows.

Possible generated/derived maps:
- albedo/base color;
- normal;
- roughness;
- metallic;
- ambient occlusion;
- height/parallax;
- curvature.

These are **source maps**. Skyrim's actual texture-slot semantics depend on:
- vanilla BSLightingShaderProperty type/flags;
- ENB workflow;
- Community Shaders Complex Materials/PBR/TruePBR;
- ParallaxGen/PGPatcher;
- NIF texture-set layout.

Do not blindly drop a standard Unreal/Unity PBR material set into Skyrim slots.

## Source-image requirements

Preserve:
- prompt;
- model/checkpoint;
- model hash/version when available;
- LoRAs;
- workflow JSON;
- seed;
- source/reference images;
- mask;
- generated dimensions;
- color-space assumptions;
- license/permission evidence.

## Seamless/tileable textures

Automated tests:
- tile 3x3 and calculate border discontinuity;
- inspect color/normal seams;
- verify mip-level seam persistence;
- render on representative tiled mesh;
- vision-assisted seam review.

AI can repair seam candidates through inpainting/offset workflows, but final pass is deterministic border/error analysis + visual review.

## Normal maps

Validate:
- tangent-space convention;
- channel orientation expected by target workflow;
- normalized vectors;
- no baked lighting unless deliberately desired;
- alpha-channel semantics for the target Skyrim shader/material.

Do not infer that an OpenGL normal generated by a generic PBR workflow is directly correct for a Skyrim/DirectX material.

## Height/parallax

Validate:
- grayscale range;
- tiling;
- absence of obvious lighting contamination;
- scale relative to material;
- intended vanilla parallax vs Complex Material/PBR workflow;
- ParallaxGen compatibility.

## DDS conversion — DirectXTex/texconv

Use `texconv` as deterministic conversion/inspection backend where appropriate.

Agent responsibilities:
- select format from texture role and target renderer;
- generate mipmaps;
- preserve sRGB vs linear intent;
- inspect dimensions/alpha;
- write to staging;
- decode/read back.

Never have an image model output DDS directly as the trusted release artifact.

## Compression policy

Compression choices are project/material specific.

The factory should infer from:
- texture role;
- alpha requirement;
- quality target;
- Skyrim runtime/renderer support;
- source precision;
- size/performance budget.

Store the chosen DDS format and reasoning in the build report.

## Texture path closure

For every NIF/TXST/material:
1. parse referenced paths;
2. resolve through VFS/BSA;
3. identify winning asset;
4. verify DDS loads;
5. verify expected map role;
6. flag duplicate/stale/generated paths.

## Material preview

Preferred pre-game loop:
1. load representative NIF in Blender/PyNifly;
2. apply generated source maps;
3. render multiple angles/light directions;
4. AI vision proposes changes;
5. deterministic map checks rerun;
6. export NIF/DDS;
7. NifSkope independent load;
8. in-game fixture under target renderer.

## Renderer fixtures

For material mods keep fixtures for:
- vanilla renderer if supported;
- Community Shaders configuration/version;
- ENB if explicitly supported;
- indoor/outdoor;
- daylight/night;
- wetness/snow/parallax where relevant.

## Automated defect checks

Detect:
- missing mipmaps;
- wrong dimensions;
- unexpected alpha;
- invalid DDS container;
- duplicate/unused texture;
- missing VFS resource;
- wrong texture slot;
- normal-map channel/normalization anomalies;
- obvious tiling seam;
- extreme map values;
- generated output older than source/workflow;
- NIF material referring to a different source texture family than the manifest.

## AI texture regression test

A generated asset is release-candidate only after:
- workflow/provenance captured;
- source PNG/TIF retained;
- DDS conversion reproducible;
- NIF/TXST paths resolve;
- independent image decode succeeds;
- render preview passes;
- target renderer fixture passes;
- rights gate passes.

## Useful integrations

- Comfy-Org/comfy-mcp — local ComfyUI MCP.
- ComfyUI TextureAlchemy — PBR map extraction/processing workflows.
- microsoft/DirectXTex/texconv — deterministic conversion/mip/compression.
- Blender MCP — material assignment/render iteration.
- PyNifly/NifSkope — Skyrim NIF validation.
- ParallaxGen/PGPatcher — final mesh/material patch generation.
