# Skyrim Modding Terminology — LOD, Grass, Occlusion, and World Rendering

Imported: 2026-09-24
Status: sourced deep-ingestion pass 3

## LOD hierarchy

### Terrain LOD
Distant terrain geometry/textures.

### Object LOD
Combined distant meshes/textures for statics and other eligible references.

### Tree LOD
Dedicated distant-tree representation.

### Grass LOD
Grass billboards/placements incorporated into object-LOD generation through modern DynDOLOD workflows.

### Dynamic LOD
DynDOLOD-managed distant references that can switch among LOD/full/specialized models at runtime.

### NearGrid
DynDOLOD dynamic grid just outside active exterior cells.

### FarGrid
Farther dynamic grid; behavior relative to large reference distance differs by runtime/config.

### LOD level
Distance tier. Terrain/object LOD use multiple levels (commonly LOD4/8/16/32 concepts).

### LOD mesh
Optimized distant mesh generated for a level/tile.

### LOD texture atlas
Texture combining multiple distant object textures to reduce draw/material cost.

### Billboard
Flat/low-complexity distant visual representation, heavily used for tree/grass LOD.

### 3D tree LOD
Tree LOD using dedicated 3D LOD models rather than conventional flat billboards.

### Full model tree
Using near/full tree geometry as distant representation; high quality but expensive and can increase generation/runtime resource use.

## Large references

### Large reference
Reference selected in WRLD RNAM data to keep full models visible outside active exterior cells.

### RNAM large-reference list
Worldspace record data listing eligible large references.

### uLargeRefLODGridSize
INI setting controlling large-reference grid distance.

### fLargeRefMinSize
Engine threshold related to object bounds/scale eligibility for large-reference behavior.

### Large reference bug
Vanilla SSE/AE/VR issue where modified large references can cause full model and object LOD to coexist or full models to fail, particularly when overwritten by non-master plugins.

### Large reference bugs workaround
DynDOLOD DLL NG runtime mitigation for known large-reference system defects.

### Master requirement
DynDOLOD documents that proper large-reference definitions rely on ESM-flagged master behavior; large-reference data in non-master plugins is not used correctly by the vanilla system.

## Grass cache

### Grass cache
Precomputed per-cell grass-placement data used to render grass outside ordinary loaded cells and to generate grass LOD.

### CGID
Grass cache file extension used by current Skyrim grass-cache workflows.

### No Grass In Objects / NGIO
Framework historically used to generate/use cached grass placements and prevent grass in excluded objects/areas.

### UseGrassCache
Configuration enabling cached grass usage.

### OnlyLoadFromCache
Configuration preventing runtime regeneration and requiring cache data.

### DynDOLODGrassMode 1
Full grass extends to edge of active exterior cells; grass LOD starts beyond. Better performance.

### DynDOLODGrassMode 2
Full grass extends toward large-reference distance; grass LOD starts farther out. Better continuity/visual distance at higher cost and interacts with large-reference bugs.

### Grass billboard
Distant flat representation generated by TexGen for use in grass LOD.

### Grass LOD density
Fraction/percentage of cached grass placements represented in distant LOD.

### Grass brightness mismatch
Difference between full grass and grass LOD caused by billboard lighting/color, weather, ENB/rendering, texture generation or settings.

## Occlusion

### Occlusion
Avoiding rendering geometry hidden behind other large geometry.

### Occlusion plane
Manually placed invisible plane used by engine occlusion.

### Occlusion box
Volume used to suppress rendering of obscured content.

### TVDT
Exterior CELL field containing precomputed LOD occlusion visibility data.

### Occlusion data
Per-cell/worldspace data indicating whether groups of distant LOD tiles should render given large blockers such as mountains.

### Occlusion generation
xLODGen/DynDOLOD process calculating TVDT from terrain/object geometry.

### Occlusion quality
Sampling level affecting generation time and how aggressively hidden distant tiles are identified.

### Frustum culling
Skipping objects outside camera view.

### Occlusion culling
Skipping objects hidden by other geometry.

## DynDOLOD workflow terminology

### TexGen
Generates LOD textures, billboards and supporting assets.

### DynDOLOD generation
Analyzes load order/world references and generates plugins/assets for object/tree/dynamic LOD.

### LODGen
Native generation component producing combined LOD meshes.

### DynDOLOD Resources
Required resource package containing rules/assets/scripts supporting generation.

### DynDOLOD.esm
Master component used by current DynDOLOD setups, including large-reference-compatible data.

### DynDOLOD.esp
Generated plugin containing dynamic/LOD support data.

### Occlusion.esp
Optional dedicated plugin for generated TVDT occlusion data.

### Mesh rule
DynDOLOD rule deciding whether/how references use object LOD, dynamic LOD, full models, NearGrid/FarGrid etc.

### Billboard rule
Rule/asset definition controlling distant tree/grass representation.

### Reference handle cap
Engine limit related to loaded reference handles. Very large load orders/world mods can approach it; excessive generated references can worsen pressure.

### HITME
**Expansion:** HIgher Than Master Entry. DynDOLOD/xEdit error terminology for an internal FormID exceeding a master's valid range relationship.

### Invalid asset
Missing/corrupt/incompatible mesh/texture/script discovered during generation. DynDOLOD treats many such errors as source-mod problems rather than something generation should silently ignore.

## Terrain underside

### Terrain underside
Generated geometry below terrain intended to block seeing through gaps/holes from below or at extreme views.

### Terrain underside quality
Resolution setting balancing coverage/performance and risk of underside geometry peeking through.

## Diagnostic rules

1. Identify which distance system is wrong: full model, large reference, dynamic NearGrid/FarGrid, object LOD, tree LOD, grass LOD, or terrain LOD.
2. Large-reference bugs are not fixed by regenerating textures alone.
3. Grass LOD requires compatible grass cache and billboards; mode used during generation is baked into object LOD.
4. Occlusion data affects whether distant LOD is rendered, not nearby full models.
5. Regenerate relevant LOD after worldspace/landscape/object changes that affect generated data.
6. Treat DynDOLOD errors as provenance clues to source assets/plugins; do not automatically suppress errors.
7. Excessive full models in LOD can explode generation memory and runtime cost.
8. Parent/child worldspaces require special handling for references/LAND/LOD.
