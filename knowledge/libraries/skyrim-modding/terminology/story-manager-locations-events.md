# Skyrim Modding Terminology — Story Manager, Locations, and Event-Driven Quest Starts

Imported: 2026-09-24
Status: sourced deep-ingestion pass 6

## Story Manager

### Story Manager
Creation Engine system that receives gameplay events and evaluates configured quest/node trees to start or select quests dynamically.

### Story Manager Event
Engine event category such as Change Location, Kill Actor, Craft Item, Dialogue, Increase Skill, Add to Player and other gameplay actions that can trigger Story Manager evaluation.

### Story Manager node
Entry in the Story Manager tree that contains conditions/selection logic and child nodes or quests.

### Branch node
Node grouping child nodes/quests under shared conditions or selection behavior.

### Quest node
Story Manager node whose candidates are quests eligible to start from the triggering event.

### Random selection
Node behavior selecting among eligible candidates according to configured rules rather than deterministic first match.

### Priority
Ordering/selection weighting that can affect which node/quest is considered when multiple eligible content paths exist.

### Event data
Forms/values supplied by the event to conditions and quest alias filling, such as actor, location, item or other context.

### Change Location Event
Story event sent when an actor—usually the player—enters a new Location, providing old/new location context.

### Kill Actor Event
Story event generated by qualifying actor deaths/kills and exposing event participants to quest start logic.

### Craft Item Event
Story event generated when the player crafts an item, allowing dynamic quests/reactions based on crafted form/workbench context.

### Dialogue Event
Story event related to dialogue interactions used by radiant/dynamic systems.

### Increase Level Event
Story event produced when the player increases level.

### Increase Skill Event
Story event generated by skill advancement.

### Script Event / SendStoryEvent
Papyrus/API-triggerable Story Manager event allowing scripts to explicitly request evaluation of story-manager content.

### SendStoryEventAndWait
Papyrus pattern that waits for Story Manager processing/result where supported; latent/wait semantics should be considered.

### Radiant quest
Quest whose targets/locations/actors are dynamically selected from aliases/conditions/event context rather than entirely hard-coded.

### Radiant Story
Bethesda's broad dynamic quest/event system combining Story Manager, quest aliases, locations, conditions and procedural selection.

## Quest start semantics

### Start Game Enabled
Quest starts automatically rather than via Story Manager/manual script.

### Run Once
Quest configuration preventing ordinary restart after completion/stop.

### Allow Repeated Stages
Quest behavior controlling whether stages can be set/re-fired repeatedly.

### Stop quest
Ends running quest state and releases/tears down aliases according to engine behavior.

### Reset quest
Resets quest state/aliases according to quest API behavior; not equivalent to deleting save state.

### Restartable quest
Quest designed to stop/reset and start again with newly filled aliases.

### Quest startup stage
Initial logic/stage fragments run as quest begins; expensive startup work can affect load/event timing.

### Quest shutdown
Lifecycle when a quest stops and aliases/scripts receive shutdown-related behavior.

## Alias fill from event/location

### Event alias
Alias whose fill can be based on forms supplied by Story Manager event data.

### Find Matching Reference
Alias-fill strategy that searches candidate references matching conditions.

### Find Matching Location
Location alias fill strategy using location conditions/context.

### From Event
Alias fill mode using actor/location/reference data supplied by the triggering Story Manager event.

### External alias
Alias linked to an alias in another running quest.

### Alias dependency
One alias fill relies on another alias being filled first.

### Allow Reserved
Alias option controlling whether already-reserved references can be selected.

### Reserve reference
Quest alias ownership/reservation preventing conflicting radiant content from selecting the same reference depending on alias rules.

## Location systems

### Location hierarchy
Parent/child Location records representing nested semantic areas such as hold → city → interior/location.

### Location keyword
Keyword classifying a Location for conditions/radiant selection.

### LocRefType
Keyword-like semantic role assigned to a placed reference within a location.

### Location Ref Type lookup
Quest/alias logic that finds a reference with a required LocRefType inside a selected Location.

### Location cleared
State indicating clearable location completion, used by conditions/events and respawn behavior.

### Clearable location
Location configured/keyworded so clear state can be tracked.

### Encounter Zone link
Location/cell association to encounter-level/reset data.

## Failure modes

### No eligible Story Manager node
Event fires, but conditions filter out every candidate.

### Quest already running
Candidate radiant quest cannot start again because current quest state/config blocks it.

### Alias fill failure
Quest selected but required aliases cannot resolve, preventing successful startup or producing partial behavior.

### Reserved-reference conflict
Desired radiant target is already reserved by another quest/alias.

### Bad location metadata
Missing/misassigned Location/LocRefType/keyword prevents radiant logic from finding expected targets.

### Event not generated
Gameplay action does not produce the expected Story Manager event under that circumstance.

### Script event mismatch
SendStoryEvent targets wrong event/keyword/context or event data fails its conditions.

### Story Manager latency
Quest start may occur around loading transitions; CK Papyrus documentation notes post-load processing time can affect setup for quests started near load doors.

## Diagnostic rules

1. A radiant quest “not starting” can be event generation, Story Manager conditions, quest state, alias fill, location metadata or reservation—not merely Papyrus.
2. Inspect event inputs and alias conditions together.
3. Quest scripts may never run because the quest failed before successful alias/start initialization.
4. LocationRefTypes and Location hierarchy are semantic query data, not decorative CK metadata.
5. Established saves can preserve running/stopped/radiant quest state that changes test results.
6. Do not spam Story Manager events from polling scripts when a native gameplay event already exists.
