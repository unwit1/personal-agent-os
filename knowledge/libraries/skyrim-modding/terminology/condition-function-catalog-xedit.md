## Interpretation rules

- A condition function's presence in xEdit's table establishes its encoded index/name/parameter schema for this source version; it does not prove every function is useful in every condition context.
- `Run On` target is stored separately from the function index/parameters.
- Some functions are legacy, engine-internal, or only meaningful through perk/event-specific condition contexts.
- SKSE condition indices are separate from ordinary Papyrus native function registration.
- When a later xEdit release changes this table, keep both snapshots and diff by numeric index as well as name.
