# Skyrim Modding Knowledge — Development Toolchains, Papyrus Compilation, C++ SKSE Builds, and Debugging

Imported: 2026-09-24
Status: sourced encyclopedia pass 5

This module covers how Skyrim mod code is built rather than only what it does at runtime.

## Papyrus development

### Papyrus compiler
Bethesda compiler converting PSC source into PEX bytecode for Skyrim's Papyrus VM.

### PapyrusCompiler.exe
Creation Kit-distributed command-line compiler executable used by CK and external build tooling.

### Flags file
Compiler configuration defining Papyrus conditional/debug/user flags known to the compiler.

### TESV_Papyrus_Flags.flg
Standard Skyrim compiler flags file used during PSC compilation.

### Import path
One or more source directories searched by the compiler for parent scripts and dependency declarations.

### Source/Scripts
Modern/common source-tree location for PSC files in Skyrim SE installations/tooling.

### Scripts/Source
Legacy/alternate path convention present in older Skyrim/CK setups and mods.

### Compiled Scripts
Data/Scripts path containing runtime PEX files.

### Native declaration
Papyrus function declared `native` and implemented by engine/SKSE DLL rather than PSC body.

### Missing parent script
Compiler cannot resolve `extends` dependency from import paths.

### Missing native source stub
Compiler lacks PSC declaration for a native framework API even though the DLL may exist at runtime.

### Compile-time dependency
PSC/source required to compile a script.

### Runtime dependency
PEX/native DLL/form actually required when the compiled script executes.

### Compiler warning
Papyrus compiler diagnostic that may not stop output but can indicate suspicious type/control-flow issues.

### Compiler error
Failure preventing valid PEX generation.

### DebugInfo
Papyrus compiler/debug metadata useful for development/debugging, depending on compile settings.

### Optimization
Compiler option affecting generated bytecode; debug/release compilation settings can differ.

### Fragment compilation
Creation Kit manages generated script names/functions for quest/topic/scene/package fragments.

### Fragment source preservation
Keep generated PSC/source in version control when possible so changes can be audited/recompiled.

### External Papyrus build
Compiling PSC files outside the CK through command line/build orchestration for reproducible builds.

### Papyrus project
Manifest/build definition used by third-party tooling to collect source/import/output/settings.

## C++/SKSE toolchain

### MSVC
Microsoft Visual C++ toolchain and ABI used by Bethesda's Windows executable and most native SKSE plugin builds.

### Visual Studio
Common Windows IDE/toolchain installation for SKSE C++ development.

### CMake
Cross-platform build-system generator used by CommonLibSSE-NG and most modern native plugin projects.

### CMake preset
Named configure/build settings stored in CMakePresets.json.

### vcpkg
C/C++ dependency manager commonly used for CommonLibSSE-NG, fmt/spdlog and other plugin dependencies.

### vcpkg manifest
vcpkg.json declaring dependencies/version constraints for one project.

### VCPKG_ROOT
Environment variable pointing build scripts/CMake to vcpkg installation.

### Git submodule
Git mechanism pinning dependency source at a specific commit inside a project.

### Dependency pinning
Locking CommonLib/vcpkg/other dependencies to known revisions for reproducible builds.

### CommonLibSSE-NG
Modern reverse-engineering/helper library used as a static build dependency while the end user still runs SKSE/Address Library.

### add_commonlibsse_plugin
CommonLibSSE-NG CMake helper generating appropriate SKSE plugin declaration/build integration.

### PluginVersionData
SKSE/CommonLib plugin metadata describing name/version/runtime compatibility and Address Library/update-structure requirements.

### SKSEPluginLoad
Native plugin entry point called by SKSE.

### kPostLoad
SKSE message sent after plugins load, useful for requesting APIs from other plugins.

### kDataLoaded
Lifecycle message after game data/plugins have loaded, common initialization point for form-dependent setup.

### C++ event sink
Object registering with Skyrim/SKSE event source and receiving typed events.

### TES event
Native engine event such as equip/hit/death/menu/etc. exposed through reverse-engineered event sources.

### SKSE messaging
Lifecycle/inter-plugin message system.

### RegistrationSet
CommonLib/SKSE abstraction for serializable event registrations/callback relationships to Papyrus.

### Papyrus native registration
Binding C++ function implementation to Papyrus VM name/class/function.

### Log
Per-plugin file recording lifecycle, errors and state; modern CommonLib projects commonly use spdlog.

### spdlog
C++ logging library used by CommonLibSSE ecosystem.

### fmt
Formatting library underlying many structured log statements.

### PDB
MSVC/Windows program database containing debug symbols used by debugger/crash logger.

### RelWithDebInfo
Build configuration combining optimization with debug symbols, useful for distributable test builds.

### Debug build
Less-optimized build with assertions/debug information; behavior/performance can differ from release.

### Release build
Optimized production build.

## Cross-runtime development

### Single-binary multi-runtime
One CommonLibSSE-NG DLL supporting SE/AE/VR through runtime-aware layouts/relocations.

### Runtime-targeted build
Separate DLL compiled for one ABI/runtime family.

### UsesAddressLibrary
Plugin metadata indicating relocations depend on Address Library rather than hard-pinned raw executable version.

### UsesUpdatedStructs
CommonLibNG compatibility metadata indicating support for updated post-1.6.629 struct layouts where applicable.

### ABI-compatible compiler
Compiler configured to emit Windows/MSVC-compatible calling conventions/object layout.

### clang-cl
Clang driver emulating MSVC command-line/ABI, used by some CommonLibSSE-NG cross-build workflows.

### Cross-compilation
Building Windows Skyrim DLLs from non-Windows host while targeting correct PE/MSVC ABI.

### xwin
Tool fetching Windows SDK/MSVC CRT components for cross-compilation environments.

### PE32+ DLL
64-bit Windows Portable Executable DLL output required for SkyrimSE.exe process.

### Build success vs runtime correctness
A plugin can compile/link cleanly but still crash in game from wrong offsets, layouts, lifecycle or ABI assumptions.

## Native debugging

### Visual Studio debugger
Can attach/launch Skyrim to inspect native call stacks, breakpoints, memory and exceptions.

### WinDbg
Microsoft native debugger particularly useful for minidumps/postmortem analysis.

### Minidump
Captured process state at crash, richer than a text log for developers.

### Symbol server/cache
Location from which debugger/logger resolves matching PDB symbols.

### Breakpoint
Debugger instruction stop at selected source/address.

### Conditional breakpoint
Stops only when specified runtime expression/state matches.

### Watchpoint/data breakpoint
Break when memory location changes/accessed, useful for corruption/lifetime analysis.

### Disassembly
Machine instructions corresponding to executable code.

### Decompiler
Tool attempting high-level reconstruction from binary code.

### IDA / Ghidra
Reverse-engineering tools commonly used to inspect Skyrim executable structure/functions.

### RTTI analysis
Using C++ runtime type metadata to reconstruct engine class inheritance/names.

### Signature/pattern
Byte sequence locating code independent of one raw RVA, within limits.

### Unit test
Test native logic outside game when logic does not require runtime objects.

### Integration test
Runs plugin in Skyrim/test harness to verify engine lifecycle/interactions.

## Reproducible build rules encoded for Agent OS

1. Commit CMake/vcpkg manifests and dependency pins.
2. Keep exact CommonLibSSE-NG revision/release associated with shipped DLL.
3. Ship matching PDB when author policy permits; it dramatically improves crash diagnosis.
4. Test claimed runtimes in-game; compilation does not prove ABI/runtime support.
5. Separate compile-time PSC stubs from actual runtime DLL requirements.
6. Never edit/recompile shared framework base PEX merely to customize one mod.
7. Treat fragment scripts as generated source that still needs version-control/audit.
8. Use logs for lifecycle milestones so “DLL loaded but feature failed” can be localized.
9. Keep a clean deployable package generated by the build, not hand-copied development files.
10. Automate structural builds/tests but retain real-game integration tests for hooks/forms/UI.
