# Skyrim Modding Terminology — Footsteps, Surface Materials, and Foley

Imported: 2026-09-24
Status: sourced deep-ingestion pass 22

## Footstep architecture

### Footstep
Sound event generated by animation/movement when actor's foot contacts a surface.

### FootstepSet
Form grouping footstep sound descriptors by movement/surface behavior.

### Default Footstep Set
Default Object entry (DFTS) supplying fallback footstep behavior.

### Footstep sound
SoundDescriptor selected by active footstep set and surface/material context.

### Footstep event
Animation event/behavior marker that requests one foot-contact sound.

### Left foot event
Animation event for left-foot contact.

### Right foot event
Animation event for right-foot contact.

### Walk footstep
Footstep variant for walking speed/state.

### Run footstep
Footstep variant for running.

### Sprint footstep
Footstep variant for sprinting.

### Sneak footstep
Footstep variant for sneaking.

### Jump/land footstep
Contact sound triggered by takeoff/landing states depending on animation/event setup.

### NPC footstep
Footstep profile for non-player actors.

### Player footstep
Footstep profile for player; first-person and third-person event paths can differ.

## Surface/material routing

### MaterialType / MATT
Surface-material classification used by physics, footsteps and impact systems.

### Havok material
Collision-shape material value embedded in NIF/bhk data determining what surface the engine thinks was contacted.

### Chunk material
Per-chunk material assignment inside compressed mesh collision.

### Collision material mismatch
Visible floor appears wood/stone/etc. but collision data is tagged as another material, producing wrong footsteps/impacts.

### Unknown material
Collision material lacks usable mapping, potentially producing missing/default sounds.

### Material 0
Unset/invalid material value that can cause missing footstep/impact feedback.

### Stone
Surface category.

### Wood
Surface category.

### Metal
Surface category.

### Dirt
Surface category.

### Gravel
Surface category.

### Snow
Surface category.

### Ice
Surface category.

### Grass
Surface category.

### Sand/mud
Surface category added/expanded by audio overhauls.

### Carpet
Interior surface category used by some footstep mods.

### Water/puddle
Surface category for wading/shallow-water footsteps.

### Material inheritance
Collision tree/shapes may assign materials at different hierarchy levels; inspect actual collision chunk used by contact.

## Armor/foley layer

### Foley
Everyday movement sound such as clothing/armor rustle distinct from surface contact.

### Armor footstep layer
Sound associated with worn armor/clothing type, potentially layered with surface footstep.

### Clothing foley
Fabric movement sounds.

### Light armor foley
Lighter equipment rustle/clatter.

### Heavy armor foley
Heavier metal/leather clatter.

### Barefoot set
Footstep profile without boot/armor layer.

### High-heels footstep
Custom footstep set/effect replacing ordinary shoe contact for eligible actors/outfits.

### Armor Addon footstep
ARMA can carry/relate to footstep set data; SRD supports runtime replacement of ArmorAddon footstep fields.

### Boot-only routing
Vanilla/older setups can derive some footstep identity from boots/equipment.

### Chest-armor foley routing
Immersive Sounds-style architecture separates chest armor rustle from actual surface foot contact.

## Audio routing

### SoundDescriptor
Actual sound configuration/file selection used by footstep entries.

### SoundCategory
Category controlling volume/attenuation for footstep/foley sounds.

### Static Attenuation
SoundOutput/category setting reducing volume with distance.

### db Variance
Random volume variation.

### 3D attenuation
Distance/spatial falloff.

### Player-only unattenuated footsteps
Modern runtime tweak can make local player's footstep category clear regardless of distance attenuation while affecting same category globally depending on implementation.

### Muffle
Gameplay stealth effect reducing NPC detection noise. It does not automatically guarantee player-facing audio is silent.

### Detection noise vs audible sound
Engine stealth/detection event and actual played SoundDescriptor are separate systems.

## Runtime frameworks

### Sound Record Distributor footstep
SRD can replace ArmorAddon footstep sound fields at runtime.

### SPID footstep effect
Distribution of spell/effect that changes footstep behavior for selected actors.

### Footstep condition
Sound/record condition such as actor sex, equipment, muffle or other context used to choose/suppress sound.

### Airborne suppression
Native hook suppressing footstep animation events when actor is not grounded.

## Common failures

### Wrong footstep
Collision material tagged incorrectly.

### Missing footstep
Material unknown/0, no mapped sound, missing event or missing asset.

### Footsteps while airborne
Animation event fires after actor leaves ground; runtime fix can suppress based on grounded state.

### First-person missing sound
FP animation/event path lacks corresponding footstep setup while third person works.

### Surface mismatch
One mesh's collision chunks use inconsistent MATT values.

### Footstep overwrite
Audio overhaul/mesh fix/runtime distributor changes one layer after another.

### Silent collision impact
Same bad material can affect both footstep and weapon/projectile impact feedback.

## Diagnostic rules

1. If the sound is wrong only on one floor/mesh, inspect NIF Havok material before audio plugin records.
2. If all surfaces are wrong for one actor/outfit, inspect FootstepSet/ArmorAddon/equipment layer.
3. Detection Muffle and audible player footsteps are separate.
4. Mesh material fixes can have no ESP at all, so xEdit may show nothing.
5. SRD/runtime changes can replace footstep data after static load.
6. Test first- and third-person separately when only player is affected.
7. Surface material also influences impact effects; wrong footsteps can reveal a broader collision-material error.
