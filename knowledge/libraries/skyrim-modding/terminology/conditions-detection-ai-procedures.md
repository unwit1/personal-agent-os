# Skyrim Modding Terminology — Conditions, Detection, and AI Procedures

Imported: 2026-09-24
Status: sourced deep-ingestion pass 9

## Condition system

### Condition
Engine-evaluated predicate row used by dialogue, quests, packages, perks, magic effects, crafting, Story Manager and many other systems.

### Condition list
Ordered collection of condition rows.

### AND condition
Default relationship where all required rows/groups must evaluate true.

### OR flag
Condition-row flag grouping alternatives so one matching branch can satisfy the condition logic.

### Subject
Condition Run On target representing the object/actor currently being evaluated.

### Target
Alternative Run On target supplied by the parent system/event.

### Reference
Condition explicitly evaluates against a selected reference.

### Combat Target
Run On context using an actor's combat target.

### Linked Reference
Run On context using linked-reference relationship.

### Quest Alias
Run On context evaluating the reference currently filling an alias.

### Event Data
Condition target sourced from Story Manager/game event parameters.

### Package Data
Condition target sourced from current AI package parameters.

### Comparison value
Right-hand value tested against the condition function's result.

### Global comparison
Condition compares result against a GlobalVariable rather than a literal numeric value.

### Condition function
Native engine function producing a value for a condition row, such as GetIsID, HasKeyword, GetInFaction, GetStageDone or GetDistance.

### Condition parameter
Form/int/actor-value/etc. argument required by a condition function.

### Condition evaluation frequency
How often conditions are rechecked depends on the parent system. Magic spell-side/effect-side conditions, packages, dialogue and perks have different lifecycles.

### Condition side effect
Conditions should generally be queries; any function with side effects is inappropriate/unsupported as a conventional condition function.

### GetIsID
Tests whether evaluated object has a specific base identity.

### GetIsReference
Tests exact reference identity.

### GetInFaction
Tests faction membership.

### GetFactionRank
Returns rank in a faction.

### HasKeyword
Tests keyword membership.

### HasPerk
Tests perk membership.

### HasSpell
Tests spell/ability membership.

### HasMagicEffect

## Detection

### Detection
Engine stealth/perception system determining whether actors perceive targets/events.

### Detection value
Combined score involving target/source skill, visual factor, sound factor and distance attenuation.

### Visual factor
Contribution based on visibility/light/movement and detection settings.

### Sound factor
Contribution generated by movement/action noise and Detection Events.

### Actor skill factor
Detection contribution from detecting actor's perception-related stats/skills.

### Target skill factor
Sneak/target contribution reducing detection.

### Distance attenuation
Detection contribution scales down with distance.

### Detection Event
Sound/action event at a location that can alert hostile actors even without direct visual detection.

### Action rating
"Loudness"/strength attached to a Detection Event, often from projectile/explosion/action data.

### Alert state
Actor has noticed suspicious event/near-detection and searches/raises awareness.

### Combat detection
Detection sufficient to establish/maintain combat target.

### Lost state
Combatant lost visual detection but searches around last-known/event locations.

### Stealth Points
Engine tracking used during combat loss/reacquisition transitions.

### Line of sight
Visibility test influencing visual/sound detection calculations.

### Detection event owner
Actor responsible for the noise/event and used to determine hostility response.

## Package diagnostics

### Package eligibility
Conditions/schedule/data all allow package to run.

### Package priority
Actor/package-stack ordering determining which eligible package wins.

### Package interrupt
Higher-priority/combat/quest behavior displaces current package.

### Package evaluation
Engine chooses current package based on available stacks and conditions.

### EvaluatePackage
Forces reevaluation; does not repair navmesh or automatically clear combat.

### Package target failure
Configured target/location cannot resolve.

### Package path failure
Package is valid but actor cannot navigate to target.

### Package state persistence
Current actor/reference/quest state in save can alter package behavior after mod updates.

## Diagnostic rules

1. Always identify the parent context of a condition; evaluation cadence/context differ.
2. An AI package can be valid yet fail because navmesh/collision blocks the route.
3. Detection problems should be split into visual, sound/event, hostility and combat-state layers.
4. ForceGreet failures can be package eligibility, pathing, dialogue conditions or target selection.
5. EvaluatePackage is useful only when stale package selection is suspected.
6. Do not use scripts to poll conditions that the engine can evaluate natively unless there is a specific need.
